Security

Three layers of authorization, enforced on the server

Legacy DMS security stops at hiding menu items. Bodhi DMS enforces every rule at the API — the screen is just a convenience.

Layer 1 — Identity

Token-based authentication

Short-lived JWT sessions with refresh rotation. Passwords stored as salted hashes — never plaintext, never recoverable, never returned by any API.

Layer 2 — Module rights

The rights matrix, actually enforced

Every API resource maps to the page that owns it. A user outside a module gets 403 from the server — not just a hidden menu. Configured per user with a visual rights editor.

Layer 3 — Field rules

Down to the individual field

Admins declare which fields are mandatory and which roles may write sensitive fields. Enforced globally on every create and update.

Secrets

Encrypted credential vault

GST, banking, OEM and messaging credentials live in a per-dealer vault, encrypted at rest with Fernet. The UI shows masked previews — raw secrets never leave the server.

Accountability

Audit trails built in

Who made it, who checked it, when, from where. E-invoice actions log user, IP and GSTIN per IRN. Issued documents are point-in-time snapshots that can never silently change.

Containment

Read-only by construction

The built-in SQL analyzer opens the database read-only at the engine level, allow-lists tables, and masks password columns — power without exposure.
